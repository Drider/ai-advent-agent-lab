# Сравнение стратегий управления контекстом

Отчёт рассчитан на сценарий Дня 9 из [ручного теста сжатия](chat-compaction-manual-test.md). Для честного сравнения создаётся новая сессия для каждого режима, отправляются те же 15 реплик по одной, после чего проверяются пять ответов: имя ответственной, срок, бюджет, ограничение и решение о пилоте.

Запуск при работающем Nuxt-сервере:

```bash
node scripts/compare-context-strategies.mjs > /tmp/context-strategies.json
```

Можно задать `CHAT_URL`, `LLM_MODEL`, `CONTEXT_WINDOW_TOKENS` и `CONTEXT_WINDOW_MESSAGES`. Скрипт сохраняет ID сессий, поэтому ответы и подробные usage можно перепроверить в интерфейсе. Входные и выходные токены включают ответы агента, вызовы Summary и обновления Sticky Facts; если провайдер не вернул usage, поле остаётся неполным.

Для безопасного локального контрольного прогона без передачи сценария внешнему провайдеру можно использовать mock OpenAI-сервер:

```bash
node scripts/mock-openai-provider.mjs
NUXT_LLM_API_KEY=local-test-key \\
NUXT_LLM_BASE_URL=http://127.0.0.1:4322/v1 \\
NUXT_PUBLIC_CHAT_DEFAULT_MODEL=mock-model \\
NITRO_PORT=4311 node .output/server/index.mjs
CHAT_URL=http://127.0.0.1:4311 node scripts/compare-context-strategies.mjs
```

## Результаты прогона

Заполните таблицу выводом скрипта. `Детали` — число правильных ответов из пяти; `вызовы` — ответы агента плюс дополнительные вызовы поддержки стратегии.

| Стратегия | Детали | Входные токены | Выходные токены | Вызовы агента | Доп. вызовы | Специализированный код, строк | Вывод |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| Sliding Window | 0 / 5 | 10 739 | 136 | 15 | 0 | 6 строк helper-кода + общий dispatch | Подходит, когда важнее предсказуемый бюджет и свежий хвост |
| Sticky Facts | 5 / 5 | 14 924 | 1 012 | 15 | 15 | 201 строка facts-хранилища и extractor + общий dispatch | Подходит для длинного диалога с коротким набором устойчивых фактов |
| Summary | 5 / 5 | 12 719 | 232 | 15 | 1 | 229 строк существующего summarizer/policy-кода + общий dispatch | Подходит, когда нужно сохранить широкий смысл старой истории |

Это локальный контрольный прогон на детерминированном mock-провайдере, с окном 10 сообщений. В каждой строке 15 основных вызовов модели; Sticky Facts добавляет по одному maintenance-вызову после каждой пользовательской реплики, Summary — один вызов сводки на пороге. Токены mock-провайдера рассчитаны по длине запроса и нужны для сравнения относительной стоимости, а не для оценки конкретной production-модели.

Скрипт проверяет ответы по подстрокам. Если модель повторила факт в промежуточных ответах, это отмечается отдельно: такой факт уже был доступен из окна и не является чистым тестом долговременной памяти.

## Сложность поддержки

Для количественного сравнения учитывались специализированные модули: `sliding-window.ts` — 6 строк, `facts.ts` + `facts-repository.ts` — 201 строка, `summarizer.ts` + `policy.ts` — 229 строк. Общие SQLite, UI и проверка бюджета показываются отдельно, потому что они не принадлежат одной стратегии. Дополнительные модельные вызовы видны в `facts_updates` и `compaction_attempts`.

Ожидаемый профиль затрат:

- Sliding Window не делает maintenance-вызовов и имеет самый простой путь, но забывает детали, которые выпали из хвоста.
- Sticky Facts делает отдельное обновление facts после пользовательских сообщений; это увеличивает число вызовов, но удерживает короткие ключевые данные при малом окне.
- Summary делает вызов только при пороге или приближении к лимиту; сводка лучше удерживает связный контекст, но зависит от качества пересказа и стоит дороже в момент сжатия.

## Ветвление

Под завершённым ответом ассистента нажмите «Ветка». Новая сессия получает копию истории до этой точки и ждёт нового сообщения. Повторное нажатие на ту же точку создаёт вторую ветку. В шапке ветки доступны исходный диалог и соседние ветки; удаление родителя не удаляет дочерние сессии.
