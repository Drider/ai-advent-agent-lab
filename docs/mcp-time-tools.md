# Time MCP через MCP-клиент

Time MCP Server добавляет в чат инструменты для работы с текущим временем, конвертацией часовых поясов и расчётом времени в прошлом. Приложение запускает опубликованный пакет `mcp-server-time` как stdio-процесс через `uvx`, поэтому сервер не хранится в этом репозитории.

## Быстрый запуск

### Требования

- Node.js 22.18 или новее;
- npm;
- `uvx` из [uv](https://docs.astral.sh/uv/) в `PATH` процесса Nuxt;
- доступ к PyPI при первом запуске;
- настроенные `LLM_BASE_URL` и `LLM_API_KEY` для живого запроса к модели.

Добавьте сервер времени в `.env`:

~~~dotenv [.env]
MCP_SERVERS_JSON='[{"id":"time","command":"uvx","args":["mcp-server-time"]}]'
~~~

Если Git MCP уже подключён, сохраните оба сервера в одном JSON-массиве:

~~~dotenv [.env]
MCP_SERVERS_JSON='[{"id":"time","command":"uvx","args":["mcp-server-time"]},{"id":"git","command":"node","args":["/absolute/path/scripts/git-mcp-server.mjs","/absolute/path/repository"]}]'
~~~

Прогрейте пакет до запуска приложения:

~~~bash [Terminal]
uvx mcp-server-time --help
npm run dev
~~~

Откройте `http://localhost:3535` и задайте вопрос:

~~~text [Chat]
Сколько сейчас времени в Москве?
~~~

В строке вызова инструмента проверьте имя `mcp_time__get_current_time` и аргумент `timezone: Europe/Moscow`. Следующий шаг модели должен содержать фактическую дату и время, возвращённые сервером.

## Доступные инструменты

Клиент добавляет к каждому имени префикс `mcp_time__`, чтобы избежать конфликтов с локальными инструментами и другими MCP-серверами.

| MCP-инструмент | Имя в агенте | Аргументы |
| --- | --- | --- |
| `get_current_time` | `mcp_time__get_current_time` | `timezone` — необязательная IANA-зона, по умолчанию `Europe/Moscow` |
| `convert_time` | `mcp_time__convert_time` | `time` — обязательное время в формате `HH:MM`; `source_timezone` и `target_timezone` — необязательные IANA-зоны |
| `get_time_ago` | `mcp_time__get_time_ago` | `timezone`, `days_ago`, `hours_ago`, `minutes_ago`, `seconds_ago`; все поля необязательны и по умолчанию равны зоне `Europe/Moscow` и нулевым интервалам |

Примеры запросов:

~~~text [Chat]
Сколько сейчас времени в Москве?
Сколько будет в Москве, когда в Токио 18:00?
Который час был в Лондоне 2 часа и 30 минут назад?
~~~

Используйте названия часовых поясов IANA, например `Europe/Moscow`, `Asia/Tokyo` и `America/New_York`. Если зона не существует, MCP возвращает ошибку следующему шагу модели; агент не должен придумывать результат.

## Как проходит вызов

На каждом обычном ходе чата приложение выполняет следующие шаги:

1. Читает `MCP_SERVERS_JSON` из серверного `runtimeConfig`.
2. Запускает `uvx mcp-server-time` через `StdioMCPTransport`.
3. Получает схемы через MCP protocol discovery и `tools/list`.
4. Передаёт namespaced-инструменты в `ToolLoopAgent` вместе с локальными инструментами.
5. Отправляет выбранный моделью `tools/call` через stdio.
6. Передаёт фактический результат MCP следующему шагу модели.
7. Закрывает соединение после завершения, ошибки или отмены ответа.

Клиент находится в [server/mcp/client.ts](../server/mcp/client.ts), а подключение к агенту — в [server/agent/chat-agent.ts](../server/agent/chat-agent.ts). MCP-инструменты намеренно не выдаются модели при продолжении прерванного хода и во время активной задачи.

## Таймауты запуска

Первый запуск `uvx` может скачивать пакет и занимать больше секунды. AI SDK использует короткий внутренний discovery probe, поэтому stdio-транспорт приложения явно сообщает, что discovery может ждать ответа. Общий MCP startup timeout приложения равен 60 секундам и ограничивает весь запуск, discovery и получение списка инструментов.

Это поведение предотвращает ошибку вида:

~~~text [Error]
connection is serving the 2026-07-28 protocol; the initialize handshake is not accepted
~~~

Такая ошибка означает, что клиент не дождался modern discovery и ошибочно перешёл к legacy `initialize`. После изменения `MCP_SERVERS_JSON` перезапустите Nuxt, чтобы серверный процесс перечитал конфигурацию.

## Проверка без ключа модели

Интеграционный тест запускает настоящий Time MCP Server и использует mock-модель для проверки полного цикла MCP:

~~~bash [Terminal]
RUN_TIME_MCP_INTEGRATION=1 npx vitest run tests/time-mcp.integration.test.ts
~~~

Тест проверяет обнаружение трёх инструментов, передачу реального времени в следующий шаг модели, обработку неверной временной зоны и закрытие соединения.

## Troubleshooting

### `uvx: command not found`

Установите uv и убедитесь, что каталог с `uvx` доступен процессу, который запускает Nuxt. GUI-запуск и запуск из терминала могут использовать разные значения `PATH`.

### Первый запрос долго не отвечает

Проверьте сетевой доступ к PyPI и выполните `uvx mcp-server-time --help` вручную. Приложение ждёт MCP startup до 60 секунд, но недоступный PyPI не позволит серверу запуститься.

### MCP-инструменты не появились в чате

Проверьте, что ход является обычным новым сообщением. При активной задаче или продолжении прерванного хода агент скрывает MCP-инструменты по правилам безопасности. Затем проверьте, что `MCP_SERVERS_JSON` содержит валидный JSON-массив, и перезапустите Nuxt.

### Один MCP-сервер ломает весь ход

Приложение подключает серверы последовательно до создания ответа модели. Если один сервер из массива не запускается или не проходит handshake, весь ход завершается ошибкой настройки. Для диагностики временно оставьте в `MCP_SERVERS_JSON` только Time MCP, затем добавляйте остальные серверы по одному.
