# MCP Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подключить инструменты настроенных MCP-серверов к существующему агенту и предоставить локальный MCP-сервер для просмотра Git-репозитория.

**Architecture:** Отдельный серверный модуль открывает MCP-клиентов, собирает определения инструментов и возвращает набор инструментов AI SDK вместе с функцией закрытия. `streamChatAgent` владеет этим набором на время потока и передаёт его в `ToolLoopAgent` рядом с локальными инструментами.

**Tech Stack:** Nuxt 4, TypeScript, AI SDK 7 (`ai`, `@ai-sdk/mcp`), MCP TypeScript SDK v1, Node.js, Vitest.

**Spec:** [2026-11-23-mcp-tools-design.md](../specs/2026-11-23-mcp-tools-design.md)

## Global Constraints

- MCP-конфигурация доступна только серверу и задаётся через `MCP_SERVERS_JSON`; пользовательские сообщения её не меняют.
- Первый этап поддерживает локальный stdio-транспорт.
- MCP-инструменты не доступны при `disableMutatingTools` и при открытой задаче `isTaskOpen(task)`.
- Соединение нельзя закрывать при возврате `Response`: генерация продолжает работать, пока читается поток.
- Имена инструментов стабильны: `mcp_<serverId>__<toolName>`; коллизии отклоняются.
- Git-сервер работает с одним репозиторием, заданным при запуске, и предоставляет только чтение состояния.

## File Structure

- `server/mcp/client.ts` (новый): тип конфигурации, разбор `MCP_SERVERS_JSON`, подключение, обнаружение и преобразование инструментов, закрытие клиентов.
- `server/agent/chat-agent.ts`: принимает динамические инструменты, записывает их вызовы и закрывает соединения по окончании потока.
- `server/api/chat.post.ts`, `nuxt.config.ts`, `.env.example`: передают серверную конфигурацию в потоковый агент.
- `tests/mcp-tools.test.ts`, `tests/chat-agent.test.ts`: проверяют обнаружение, вызов, возвращение результата и жизненный цикл.
- `README.md`: пример настройки и короткая ручная проверка.
- `scripts/git-mcp-server.mjs` (новый): самостоятельный stdio MCP-сервер с тремя Git-инструментами.
- `tests/git-mcp-server.test.ts` (новый): проверка настоящего MCP-соединения с временным Git-репозиторием.

## Review Focus

- Пустой список серверов: чат не открывает MCP-соединение и сохраняет прежний набор инструментов (Task 1, Task 2).
- Два одинаковых имени инструмента на разных серверах: оба доступны под разными именами (Task 1).
- Несколько страниц `listTools`: схемы инструментов с последней страницы попадают модели (Task 1).
- Ошибка подключения или обнаружения после успешного первого сервера: все открытые клиенты закрываются, ход получает ошибку (Task 1, Task 2).
- Прерванный поток: MCP-клиент закрывается после отмены, а не до вызова инструмента (Task 2).
- Некорректный или выходящий за пределы репозитория `path`: Git-сервер возвращает `isError`, не читая другой путь (Task 3).
- Репозиторий без коммитов и слишком большой diff: инструменты отвечают понятной ошибкой или ограниченным выводом (Task 3).

**Files:** Create `server/mcp/client.ts`; modify `package.json`, `package-lock.json`; test `tests/mcp-tools.test.ts`.

**Interfaces:**

- `type McpServerConfig = { id: string; command: string; args: string[] }`.
- `parseMcpServers(raw: string): McpServerConfig[]`: валидирует JSON, непустые уникальные `id` (`[a-z0-9_]+`), команду и строковые аргументы; `[]` допустим.
- `connectMcpServers(configs: McpServerConfig[]): Promise<{ tools: ToolSet; names: string[]; close(): Promise<void> }>`: имена `mcp_<id>__<toolName>`, `close()` безопасен при повторном вызове.

### Task 2: Интеграция в потоковый агент

**Files:** Modify `server/agent/chat-agent.ts`, `server/api/chat.post.ts`, `nuxt.config.ts`, `.env.example`; test `tests/chat-agent.test.ts`.

**Interfaces:**

- `createChatAgent(..., options: { mcpTools?: ToolSet; ... })`: добавляет динамические инструменты к `tools` без перезаписи локальных.
- `streamChatAgent(input: { mcpServers?: McpServerConfig[]; ... })`: вызывает `connectMcpServers`, оборачивает MCP-инструменты в `recordToolExecution`, передаёт их агенту и вызывает `close()` при `onEnd` и при ошибке подготовки; при отмене потока закрывает клиент через тот же путь.
- `chat.post.ts` читает `useRuntimeConfig(event).mcpServers`, вызывает `parseMcpServers` и передаёт конфигурацию в `streamChatAgent`. Настройка в `nuxt.config.ts` берётся из `process.env.MCP_SERVERS_JSON ?? '[]'`.

### Task 3: Локальный Git MCP-сервер

**Files:** Create `scripts/git-mcp-server.mjs`, `tests/git-mcp-server.test.ts`; modify `package.json`, `package-lock.json`.

**Interfaces:**

- Запуск: `node scripts/git-mcp-server.mjs [absolute-repository-path]`; без аргумента используется `process.cwd()`. Путь фиксируется при старте после проверки `git rev-parse --show-toplevel`.
- MCP tools: `git_status({})`, `git_log({ limit?: number })`, `git_diff({ staged?: boolean, path?: string })`.
- Все успешные ответы содержат MCP `content: [{ type: 'text', text }]`; ошибка Git или неверный `path` возвращает `isError: true`. Вывод инструмента ограничен 64 КиБ с явной пометкой об усечении.

- [x] Добавить проверки `git_diff` для `staged`, выхода `path` за пределы репозитория и большого вывода; `git_log` в репозитории без коммитов возвращает `isError`.
- [x] Запустить `npx vitest run tests/git-mcp-server.test.ts` и убедиться, что новые тесты падают из-за отсутствующего сервера.

Запускать `git` через `execFile`/`spawn` с массивом аргументов, `shell: false`, `GIT_OPTIONAL_LOCKS=0`; не писать диагностические строки в stdout.

## Self-Review

План покрывает соединение, список инструментов, передачу схем модели, выбор и аргументы модели, вызов MCP и возврат результата. Git-сервер даёт рабочий пример и проверяет цикл по настоящему stdio-транспорту. Интерфейсы `McpServerConfig`, `ToolSet` и `close()` согласованы между задачами. Отдельных изменений UI или хранилища не требуется.
