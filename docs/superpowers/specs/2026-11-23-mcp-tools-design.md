# Подключение инструментов MCP к агенту

## Задача

Агент этого Nuxt-приложения должен подключаться к настроенным MCP-серверам, узнавать доступные инструменты и передавать их схемы модели. Модель выбирает инструмент и аргументы; приложение выполняет вызов через MCP и передаёт результат в следующий шаг модели. В комплекте нужен локальный MCP-сервер для просмотра Git-репозитория.

## Текущее состояние

`server/agent/chat-agent.ts` создаёт `ToolLoopAgent` из AI SDK 7 с локальными инструментами. AI SDK уже выполняет цикл «модель → вызов инструмента → результат → модель». `server/api/chat.post.ts` запускает потоковый ответ; вызовы инструментов записываются через `recordToolExecution`.

## Решение

- Серверная переменная `MCP_SERVERS_JSON` содержит массив локальных stdio-серверов: `[{"id":"demo","command":"node","args":["/absolute/path/server.js"]}]`. Пустой массив означает обычную работу без MCP. Конфигурация не поступает из пользовательского сообщения.
- Для каждого сервера `@ai-sdk/mcp` открывает соединение через `StdioMCPTransport`. Клиент получает определения через `listTools()` и преобразует их в инструменты AI SDK через `toolsFromDefinitions()`. Пагинация `listTools` обрабатывается до преобразования.
- Ключ каждого инструмента в агенте — `mcp_<serverId>__<toolName>`. Так одинаковые имена на разных серверах и локальные инструменты не перезаписывают друг друга. При невозможности получить уникальное имя запуск хода завершается понятной ошибкой.
- В `ToolLoopAgent` передаётся общий набор локальных и MCP-инструментов. Адаптер передаёт модели исходную схему аргументов MCP, вызывает соответствующий `tools/call` при выборе модели и возвращает `CallToolResult` в цикл агента. Обёртка `recordToolExecution` сохраняет вызов и результат по принятому в проекте механизму.
- Соединения живут до конца потокового ответа. Они закрываются при успешном завершении, ошибке и отмене чтения потока. При ошибке подключения одного сервера уже открытые соединения закрываются.
- В режиме продолжения прерванного хода и во время активной задачи MCP-инструменты не выдаются модели: для внешних инструментов нельзя надёжно определить отсутствие побочных эффектов. В остальных ходах используются все инструменты настроенных серверов.

## Локальный Git MCP-сервер

- Отдельный запускаемый Node.js-процесс использует официальный TypeScript SDK MCP (`McpServer`, `StdioServerTransport`). Он принимает путь к репозиторию только при запуске; модель не выбирает репозиторий.
- При запуске путь нормализуется через `git rev-parse --show-toplevel`. Если это не Git-репозиторий, сервер завершается с понятной ошибкой в stderr. stdout используется только для MCP-протокола.
- Сервер объявляет три инструмента: `git_status` (ветка и изменённые/новые файлы), `git_log` (последние коммиты, `limit` от 1 до 20, по умолчанию 10) и `git_diff` (неиндексированные или индексированные изменения через `staged`, необязательный относительный `path`). `git_diff` не включает содержимое неотслеживаемых файлов.
- Git запускается с массивом аргументов без оболочки. Путь проверяется как относительный путь внутри выбранного репозитория и передаётся после `--`. Вывод ограничен 64 КиБ; Git-ошибка возвращается как MCP `isError`, а не как успешный пустой результат.
- Сервер только читает состояние: нет инструментов `add`, `commit`, `checkout`, `reset`, `push`. Последующая поддержка изменений Git потребует отдельного решения о разрешённых действиях.

## Границы первого этапа

Поддерживаются локальные stdio-серверы и инструменты. Управление серверами через UI, HTTP-транспорт, ресурсы и промпты MCP остаются последующими расширениями. Список доступных инструментов определяется заново на каждый ход; конфигурация доверена оператору приложения. Git-сервер обслуживает один репозиторий, заданный при запуске.

## Приёмка

1. С настроенным MCP-сервером запрос модели содержит имена, описания и схемы его инструментов.
2. Модель выбирает один MCP-инструмент и аргументы; вызов доходит до сервера, а его фактический результат присутствует в следующем запросе к модели.
3. Два сервера с одноимёнными инструментами доступны независимо.
4. Без настройки MCP существующий чат работает как раньше.
5. Соединения закрываются после завершения или отмены потока и после ошибки открытия/обнаружения.
6. Git-сервер через настоящий MCP-клиент показывает `git_status`, `git_log`, `git_diff`; ответы совпадают с состоянием временного тестового репозитория.
7. Git-сервер не выполняет команды вне выбранного репозитория и не переполняет ответ большим diff.
