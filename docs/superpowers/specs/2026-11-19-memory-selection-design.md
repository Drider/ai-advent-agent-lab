# Правила отбора памяти в промпт

Пользователь согласовал независимые правила отбора для каждого слоя.

## Правила

- Краткосрочная память: только текущий диалог по существующей выбранной стратегии. Summary, Sliding Window, Sticky Facts и режим «Выключено» сохраняют своё поведение.
- Рабочая память: доступные включённые `goal`, `constraint`, `state` текущего проекта обязательны; `note` и `result` включаются по релевантности.
- Долговременная память: доступные включённые `profile` обязательны; `knowledge` и `decision` включаются по релевантности. Доступность означает глобальное включение или связь с текущим проектом.
- Обязательные записи занимают бюджет своего слоя первыми. Остальные добавляются целиком по убыванию релевантности. При равенстве оценки используется порядок категория, ключ, ID.
- Переполнение обязательными записями отклоняет ход до сохранения реплики. Слишком большая необязательная запись пропускается; меньшие записи после неё могут попасть в бюджет.
- Причины исключения сохраняются без текста записей или запроса: `disabled`, `not_relevant`, `budget_exceeded`. Записи других проектов отсеиваются до отбора и не появляются в диагностике.

## Подход

Выбран поиск по словам в ключе и значении: он предсказуем, не требует зависимостей или дополнительных запросов к модели. Семантический поиск остаётся возможным дальнейшим улучшением.

Конкретизация реализации: запрос состоит из текущей реплики и трёх предыдущих завершённых реплик пользователя этого диалога, без повторения текущего ID. Слова нормализуются по Unicode и регистру, `ё` приравнивается к `е`; служебные слова и одиночные символы игнорируются. Оценка — число уникальных общих слов. Совпадение должно быть целым словом; морфология и синонимы не учитываются.

Предпросмотр без запроса показывает обязательную память. API предпросмотра принимает текст запроса для проверки дополнительного отбора. Это различие поясняется рядом с оценкой бюджета.

Данные сохраняются в существующих таблицах. Новая миграция добавляет JSON с причинами исключения к событиям подготовки; старые события получают пустой список. Частота включений считается только по фактически выбранным записям.

## Проверка

Тесты проверяют категории, области, отключённые записи, актуальный запрос до его сохранения, три предыдущие реплики, пустой запрос, Unicode, равные оценки, полные записи в бюджете, переполнение обязательной памяти, сохранение причин без текста и обновление существующей базы. Существующие тесты стратегий краткосрочной памяти должны оставаться зелёными.
