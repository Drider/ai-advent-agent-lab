# Развитие workflow задач

Дата: 2026-11-20. Статус: отложенные направления; основной дизайн первой версии находится в обсуждении.

Workflow задаёт допустимые этапы задачи, переходы между ними и условия выполнения действий. Этот roadmap сохраняет доработки для отдельных этапов после реализации основного управления состоянием. Порядок и детали этих доработок требуют отдельного согласования.

## Согласованная граница первой версии

- Каждая задача имеет состояние; сервер проверяет переход до его применения.
- Диалоги по умолчанию работают без явного workflow. Пользователь сам подключает процесс к текущей задаче; старая переписка остаётся контекстом, а процесс начинается с начального этапа.
- Разные типы задач используют разные процессы. Первая версия включает готовые шаблоны и возможность задавать пользовательскую структурированную схему. Генерация схем агентом остаётся на следующий этап.
- В проекте могут идти разные задачи со своими состояниями. В одном диалоге одновременно существует только одна незавершённая задача; следующая начинается после `done` или явной отмены `cancelled`. Предпочтительный сценарий — один диалог на задачу.
- Пользователь утверждает план кнопкой или точной командой. Для аналитики достаточно успешных формальных тестов. Без workflow агент может завершать задачу самостоятельно после выдачи результата.
- Анкета — необязательный workflow, который пользователь подключает так же, как любой другой процесс. Без подключения анкетирование не ограничивает работу диалога. Подключённая анкета относится только к текущему диалогу; общая готовность пользователя между диалогами в первую версию не входит.
- При проектировании переходов учитываем ACID. Вызов модели и внешние действия не входят в одну длительную транзакцию базы данных.

## Генерация и подбор схем агентом

Агент предлагает workflow по описанию задачи, чтобы пользователь мог создать новый процесс без ручного составления всей схемы. Генерация отложена по решению пользователя; самостоятельный подбор готового процесса агентом также не входит в первую версию.

При отдельном проектировании нужно определить:

- Как пользователь просматривает, исправляет и утверждает предложенную схему.
- Как агент предлагает существующий процесс и получает явное разрешение на его подключение.
- Как сервер проверяет структуру, переходы и условия до активации workflow.
- Как изменения схемы получают новую версию и влияют на уже начатые задачи.
- Как исключить ослабление действующих ограничений через генерацию или изменение схемы агентом.

## Визуализация workflow

Граф процесса помогает увидеть цепочки этапов, допустимые переходы и положение текущей задачи. Пользователь предложил вынести визуализацию в отдельный этап реализации.

Для этого этапа можно рассмотреть отображение текущего этапа и шага, ожидания пользователя или результата, паузы и истории переходов. Конкретный состав интерфейса пока не согласован.

## Визуальное редактирование

Визуальный редактор позволяет создавать и менять процесс через граф. Пользователь обозначил редактор как возможное продолжение визуализации; его реализация и объём пока не утверждены.

При отдельном проектировании нужно определить создание этапов и переходов, настройку условий, проверку ошибок, публикацию версий и поведение начатых задач после изменения схемы. Редактор должен сохранять тот же формат workflow, который проверяет сервер.

## Что учесть в основном дизайне

Следующие рекомендации сохраняют возможность добавить отложенные функции:

- Отделить описание процесса от состояния конкретной задачи.
- Использовать стабильные идентификаторы этапов и переходов; хранить подписи отдельно от идентификаторов.
- Предусмотреть версию схемы и связь задачи с применяемой версией.
- Проверять схемы и переходы общим серверным кодом независимо от способа их создания.
- Хранить историю изменений состояния, достаточную для восстановления и последующего отображения выполнения.

Эти рекомендации не заменяют согласование основного дизайна и не запускают реализацию отложенных функций.

Основные требования и предлагаемые решения собраны в [дизайне состояния задач и workflow](superpowers/specs/2026-11-20-task-workflow-design.md). Дизайн пока ожидает согласования.
