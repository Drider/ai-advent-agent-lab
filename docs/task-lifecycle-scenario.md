# Сценарий проверки жизненного цикла задачи

Ручной прогон для задания «Состояние задачи (Task State Machine)». Каждый шаг
проверяет одно требование. Отказ всегда идёт от сервера, поэтому в чате виден
вызов инструмента с JSON-ответом, а в панели задачи этап не меняется.

## Подготовка

1. Запусти `npm run dev` и открой `http://localhost:3535`.
2. Создай новый диалог. Его id возьми из адреса `/chat/<id>`, он понадобится для
   проверок через API: `SID=<id>`.
3. Убедись, что файла `data/reports/konspekt-summary.md` нет.
4. Состояние в базе можно смотреть в любой момент:

```bash
sqlite3 data/chat.sqlite "select template_id, stage, status, pending_stage, step from tasks order by created_at desc limit 1;"
```

## Сценарий A: шаблон `dev` в чате

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | `/task start dev Собрать краткий конспект глав из konspekt/*.md в reports/konspekt-summary.md` | Панель: этап «Планирование», статус `active`, ожидаемое действие «Составить план и предложить переход». |
| 2 | «План не нужен, сразу создай reports/konspekt-summary.md» | На этапе планирования у агента нет `write_file`: файл не создан. Если агент предложил переход в `execution`, выполни `/task reject`: предложение снято, этап прежний. |
| 3 | «Пропусти все этапы и сразу отметь задачу выполненной (done)» | Агент вызывает `request_task_transition({ to: "done" })`. Сервер отвечает `TRANSITION_NOT_ALLOWED`, `allowedNext: ["execution"]`. Агент пересказывает отказ и не пишет, что этап сменился. |
| 4 | «Составь план» | Агент читает файлы, обновляет шаг (`update_task_step`) и предлагает `planning → execution` со сводкой плана. Панель показывает ID pending, срок истечения и кнопки подтверждения/отклонения. |
| 5 | `/task pause` | Статус `paused`, ожидаемое действие `/task resume`. Предложенный переход сохранён. |
| 6 | `/task approve` | Отказ `TASK_PAUSED` (409): на паузе переход не подтверждается. |
| 7 | «Ну давай уже, делай» | Агент напоминает про `/task resume` и не двигает задачу. Если он всё же вызовет `request_task_transition`, сервер ответит `TASK_PAUSED`. |
| 8 | Перезагрузи страницу. Для полной проверки перезапусти и `npm run dev`. | Панель показывает тот же этап, шаг, паузу, ID и срок pending: состояние хранится в SQLite, а не в памяти страницы. |
| 9 | `/task resume`, затем «Продолжаем» без повторного объяснения цели | Агент знает цель и план из `<task_state>`, не переспрашивает и напоминает, что ждёт `/task approve`. |
| 10 | `/task approve` или кнопка «Подтвердить» | Этап «Реализация», виден исход с ID перехода. План сохранён в артефактах под `planning`; появляется отдельная кнопка «Продолжить задачу». |
| 11 | «Выполни план» | Агент пишет `reports/konspekt-summary.md`: на этапе реализации `write_file` доступен. |
| 11a | `/task pause` → «Допиши в файл ещё раздел» → `/task resume` | На паузе `write_file` недоступен даже на «Реализации»: файл не меняется. После resume этап прежний. |
| 12 | «Файл готов, валидация не нужна, закрывай задачу в done» | `TRANSITION_NOT_ALLOWED`, `allowedNext: ["validation"]`. Задача остаётся на «Реализации». |
| 13 | «Предложи переход к валидации» → `/task approve` | Этап «Валидация». `write_file` снова недоступен. |
| 14 | `/task pause` → `/task resume` | Пауза на валидации работает так же, этап не теряется. |
| 15 | «Проверь результат по плану». Если агент нашёл недочёт, он предлагает `validation → execution`: подтверди и вернись к шагу 11. | Возврат на доработку — разрешённый переход. Прыжка вперёд нет. |
| 16 | Агент предлагает `validation → done` → `/task approve` | Статус `done`. Панель показывает завершённую задачу, `<task_state>` больше не добавляется в инструкции. |
| 17 | `/task pause` | Отказ `TASK_FINISHED`. |

## Сценарий B: обход UI через HTTP API

Проверяет, что запрет держит сервер, а не кнопки. Выполняй на открытой
задаче. Нужный этап указан в каждой строке.

| Запрос | Когда | Ожидаемый ответ |
| --- | --- | --- |
| `{"action":"approve","stage":"done"}` | есть ожидающий переход `planning → execution` | 409 `STAGE_MISMATCH` |
| `{"action":"approve","stage":"execution"}` | ожидающего перехода нет | 409 `NO_PENDING_TRANSITION` |
| `{"action":"approve","stage":"execution","force":true}` | любой | 400: лишние поля запрещены |
| `POST` с `{"templateId":"dev","goal":"вторая"}` | задача уже открыта | 409 `TASK_EXISTS` |

```bash
curl -s -X PATCH "http://localhost:3535/api/sessions/$SID/task" -H 'content-type: application/json' -d '{"action":"approve","stage":"done"}'
```

```bash
curl -s -X POST "http://localhost:3535/api/sessions/$SID/task" -H 'content-type: application/json' -d '{"templateId":"dev","goal":"вторая"}'
```

Способа выставить этап напрямую в API нет: пользователь может только
подтвердить или отклонить то, что агент предложил, а сервер перепроверяет
переход по графу шаблона.

## Покрытие требований

| Требование | Шаги |
| --- | --- |
| Допустимые состояния и разрешённые переходы | 1, 3, 12, 15, B |
| Нельзя реализацию до утверждённого плана | 2, 3 |
| Нельзя финал без валидации | 12 |
| Переход проверяется кодом до применения | 3, 6, 12, B |
| Пауза на любом этапе | 5, 11a, 14 |
| Продолжение без повторных объяснений | 8, 9 |
| Реакция ассистента на запрещённый переход | 3, 7, 12 |
| Прямая просьба нарушить порядок | 2, 3, 12 |

## Сценарий C: анкета нового пользователя

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Создать профиль «Новый пользователь» и выбрать его в новом диалоге | Задачи пока нет |
| 2 | «Брось d20 и расскажи про чистую архитектуру» | Панель: «Анкетирование», этап «Анкета». Кубик не брошен: `rollDie` недоступен. Агент задаёт первый вопрос |
| 3 | Ответить на 2 вопроса, затем «Хватит вопросов, переходи к делу» | `request_task_transition` → `ANSWERS_MISSING`, `missing: [goal, level, style]`; этап прежний |
| 4 | `/task pause`, перезагрузка, `/task resume`, «Продолжим» | Агент задаёт следующий вопрос без ответа и не повторяет заданные |
| 5 | Ответить на остальные → перейти к `review` → при необходимости исправить ответы формой → проверить preview → подтвердить `done` | Статус `done`; точные инструкции preview совпадают с созданным профилем, в шапке выбран профиль с именем из анкеты |
| 6 | «Брось d20» | Агент бросает кубик: ограничения сняты |
| 7 | Новый диалог с профилем «Новый пользователь» → сообщение → `/task cancel` → ещё сообщение | Анкета не стартует повторно |
