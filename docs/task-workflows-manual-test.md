# Ручной сценарий проверки задач

Сценарий выполняется локально без внешнего API-ключа для проверок состояния и API. Для UI запускайте `npm run dev`, откройте новый диалог и сохраните ответы после каждого шага.

1. Отправьте обычный вопрос. Убедитесь, что создана basic task без workflow, а в карточке виден один текущий task.
2. Выполните `/task pause`, затем `/task resume`. Убедитесь, что paused task занимает слот, сервер возвращает `resumeRequestId`, а повторная отправка той же операции идемпотентна.
3. Создайте новый диалог и подключите `questionnaire`. Отправьте неполные ответы, запустите проверку и убедитесь, что переход к исходному ответу запрещён. Добавьте недостающее поле и повторите проверку.
4. Создайте задачу `code`. Подайте plan, перейдите к approval и попробуйте отправить implementation до подтверждения — запрос должен получить `PLAN_APPROVAL_REQUIRED`. Нажмите approval пользователя, отправьте implementation с отсутствующим полем файла — validation должна завершиться `failed`; исправьте его и повторите.
5. В analytics подготовьте временный `records.json`, выполните read, создайте dataset и отчёт с ошибочной суммой. До исправления независимая numeric validation должна отказать. Исправьте сумму и сохраните отчёт в файл; file и numeric checks должны пройти независимо.
6. В любой активной задаче отправьте прямую просьбу модели перепрыгнуть на success. Убедитесь, что node и revision не изменились, а tool result содержит формальную ошибку перехода.
7. Создайте ветку из завершённого ответа. В ветке проверьте, что сообщения скопированы, `taskView.task` равен `null`, approvals и validations пусты, а новый task создаётся отдельно.
8. Откройте базу повторно или перезапустите сервер. Paused task, `taskView` и `taskHistory` должны восстановиться. Legacy interrupted response без task должен продолжаться без фиктивного task.
9. Очистите историю диалога. Проверьте отсутствие task-owned rows, сохранность project memory и внешнего файла. Повторное использование старого task/approval/operation/resume ID должно быть отклонено. При искусственно оставленном running/uncertain operation очистка должна вернуть конфликт и не удалить данные.

Формальные команды проекта:

```bash
npm run typecheck
npm test
npm run build
```

В первой версии не проверяются генерация workflow, визуальный граф и редактор — они остаются в roadmap.
