Важное наблюдение: для подхода и версии модель выбрала категорию `note`, а не

сохранение, а не через прямой `replace`. Функционально старые значения исчезли,
но поведение отличается от идеального пути из плана.

## Устаревшие значения в ответах

По смыслу агент не использовал устаревшее значение как актуальное: **0 из 4
ошибочных ответов**.

При строгом поиске старых строк агент всё же упоминал прежние значения в
пояснениях к операции: `1 декабря` как предыдущее значение, PDF как удалённое
требование, REST как удалённый подход и v1 в истории обновления. Это не были
актуальные рекомендации, но если критерий сценария трактовать как «старое слово
не должно встречаться вообще», такой критерий не выполнен.

## Журнал и preview

До завершения задачи API журнала содержал 5 событий:

1. `replace`: дедлайн `1 декабря` → `15 декабря`.
2. `forget`: требование PDF.
3. `forget`: подход REST.
4. `forget`: версия v1.
5. `forget`: промежуточно созданная версия v2 при очистке ключа.

После отмены задачи добавились 3 события `task_cleanup` для дедлайна, GraphQL и
v2. Итого на `/memory` и через
`GET /api/memory/changes?projectId=...&limit=20` отображается **8 событий**.

Preview с ключевыми словами сценария до очистки показал 3 рабочие записи и 1
долговременный факт без исключений. В default-preview без запроса optional-записи
категорий `note` и `decision` не выбираются, поэтому он показывает только
обязательную память; это ожидаемое поведение селектора, а не потеря данных.

## Итог

Основной контракт реализации подтверждён реальным прогоном: значения обновляются,
удалённые факты не остаются в рабочем слое, журнал сохраняет историю операций,
завершение FSM чистит только working memory, а long-term memory сохраняется.

Отдельное улучшение по результатам прогона: усилить инструкцию агента или схему
выбора категорий, чтобы «подход» и «версия» сразу сохранялись как
перезаписываемые факты (`state`), а не как `note`. Также полезно разделить в
сценарии два критерия: отсутствие устаревшего значения как текущего ответа и
отсутствие самого текста устаревшего значения в пояснениях модели.

После этого прогона инструкция агента и описание `save_memory` усилены: для
текущих изменяемых подходов, версий и статусов явно требуется `state`, а для
`note` оставлены только накапливаемые наблюдения и история. Регрессионные тесты
проверяют оба контракта.
