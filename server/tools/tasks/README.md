# Инструменты жизненного цикла задач

Группа `tasks` позволяет агенту обновить текущий шаг и предложить переход
между закреплёнными этапами. Инструменты не применяют переход: его подтверждает
пользователь через панель или `/task approve`.

| Инструмент | Назначение |
| --- | --- |
| `get_task_state` | Прочитать свежий `TaskSnapshot` из SQLite без активного хода и без записи. |
| `record_task_answer` | Сохранить ответ на текущий вопрос анкеты длиной 1–500 символов. |
| `amend_task_answer` | Исправить один ответ на `review` с проверкой `expectedRevision`. |
| `update_task_step` | Сохранить текущий шаг длиной 1–500 символов. |
| `request_task_transition` | Предложить этап и передать сводку длиной 1–8000 символов. |
| `cancel_task_transition` | Отменить pending-переход по точному `pendingTransitionId`. |

Мутирующие операции привязаны сервером к текущей сессии и активному ходу. `get_task_state`
требует только сессию. Ошибки возвращаются со свежим снимком и `allowedTransitions`, чтобы агент
и интерфейс видели отказ guard без изменения SQLite.

`request_task_transition.applied=false` означает, что этап ещё не сменился. Агент передаёт полученный
`confirmationHint` буквально, не конструирует команду и после нового действия пользователя читает
`get_task_state` до сообщения о смене этапа.
