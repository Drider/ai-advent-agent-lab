# Инструменты анализа диагностических сессий

Эти инструменты работают с JSON-логами в `data/runs/` и `data/session-imports/`. Они не читают пользовательскую историю из `data/chat.sqlite`: SQLite используется интерфейсом чатов и сервером для восстановления контекста. Поэтому `LLM_LOG_LEVEL=off` может оставить диагностические файлы пустыми или отсутствующими, но не удаляет сохранённые диалоги.

`get_current_session` привязан к `runId` текущего запроса чата. Он возвращает точный путь к логу, модель и уровень логирования, текущий вопрос и уже сохранённые запросы. Поддерживает `query`, `offset` и `limit`, как `read_session_file`, и добавляет суммарные показатели сохранённых запросов. Текущий ответ записывается позже, после завершения запроса; поле `currentRequestPersisted` показывает это явно. До первой записи инструмент возвращает `saved: false` и пустой список.

Агент вызывает `find_files` с маской вроде `**/run-*.json`, чтобы найти логи в `data/`. Для выбора по метаданным `list_sessions` показывает пути, даты, модели и инструменты файлов из `data/runs/` и ранее созданного `data/session-imports/`. Затем `read_session_file` читает выбранный путь и возвращает метаданные и страницу из 1–10 запросов. Доступны `offset` и поиск `query` по тексту вопроса или ответа; длина каждого текста в результате ограничена 1000 символами.

`analyze_sessions` принимает до 20 относительных путей `paths` и агрегирует только эти файлы. Без `paths` он анализирует стандартные папки логов. Группировка — `day`, `model`, `tool` или `session`; фильтры — включительные UTC-даты `from`/`to`, точное имя `model`/`tool` и `runId`.

В результатах есть число сессий и запросов, ошибок, длительность, входные, выходные и суммарные токены, число вызовов инструментов. Для логов уровня `basic` модель и инструменты неизвестны и попадают в группу `(unknown)`. Группа `(none)` означает, что подробный лог подтверждает отсутствие вызовов инструментов.

`read_session_file` читает JSON-файл до 2 МиБ и передаёт агенту выбранные выдержки из вопросов и ответов; `analyze_sessions` возвращает только агрегаты. При совпадении `runId` в стандартных папках берётся более свежий `updatedAt`. Один анализ без `paths` просматривает до 100 файлов, пропущенные и лишние файлы отражаются в `skippedFiles` и `truncated`. Ответ содержит до 100 групп; при превышении выставляется `truncatedGroups`.
